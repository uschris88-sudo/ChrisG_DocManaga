    Getting Started

    This guide helps you get from zero to a working DocManaga integration in a few steps.

    Onboarding Flow

    Step 1: Create an API Key

    Follow the full setup guide in API Keys.

    1. Sign in to your DocManaga account.
    2. Open the developer settings section.
    3. Generate a new API key for your application environment.
    4. Store it securely (for example, in a secret manager or environment variable).

    Recommended environment variable:

    DOCMANAGA_API_KEY=YOUR_API_KEY

    Authentication

    All API requests require an API key.

    Use a bearer token in the Authorization header.

    Example header:

    Authorization: Bearer YOUR_API_KEY

    Base URL

    https://api.docmanaga.com/v1

    Step 2: Verify Authentication

    curl -X GET https://api.docmanaga.com/v1/documents \
    -H "Authorization: Bearer YOUR_API_KEY"

    Step 3: Upload a Document

    curl -X POST https://api.docmanaga.com/v1/documents/upload \
    -H "Authorization: Bearer YOUR_API_KEY" \
    -F "file=@invoice.pdf"

    Typical success response:

    {
    "id": "doc_555",
    "status": "uploaded"
}

    Step 4: Retrieve a Document

    curl -X GET https://api.docmanaga.com/v1/documents/doc_555 \
    -H "Authorization: Bearer YOUR_API_KEY"

    Typical success response:

    {
    "id": "doc_555",
    "name": "invoice.pdf",
    "size": "1.2MB",
    "created_at": "2026-01-10"
}

    Step 5: Create a Document Record With Metadata

    curl -X POST https://api.docmanaga.com/v1/documents \
    -H "Authorization: Bearer YOUR_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"name":"invoice-2026-03.pdf","folder":"billing"}'

    Typical success response:

    {
    "id": "doc_123",
    "status": "created"
}

    Step 6: Generate a Share Link

    curl -X POST https://api.docmanaga.com/v1/documents/doc_123/share \
    -H "Authorization: Bearer YOUR_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{"expires_in":"24h"}'

    Typical success response:

    {
    "share_link": "https://docmanaga.com/share/doc_123"
}

    Step 7: Add Basic Retry Handling for 429 Responses

    When you receive 429 Too Many Requests, wait and retry with backoff.

    Minimal retry example:

    # First retry after 2 seconds, then 4, then 8 if needed.

    Response Codes and Error Examples

    Common status codes:

    • 200 OK: Request successful
    • 201 Created: Resource created successfully
    • 400 Bad Request: Invalid payload or missing required fields
    • 401 Unauthorized: Missing or invalid API key
    • 403 Forbidden: API key lacks required permissions
    • 404 Not Found: Document or endpoint not found
    • 429 Too Many Requests: Rate limit exceeded
    • 500 Internal Server Error: Unexpected server-side failure

    Example error response:

    {
    "error": {
        "code": "unauthorized",
        "message": "Invalid API key provided."
    }
}
